Viva preparation: EpiClim climate–disease analysis

Everything needed to explain and defend Project 1: what we did and why, the theory behind every test and model, our results, and the questions an examiner is likely to ask, with answers.

1. The project in 2 minutes

Say this if asked "explain your project":

"We analysed EpiClim, India's weekly, district-level disease surveillance data from the Integrated Disease Surveillance Programme (IDSP), joined with rainfall, temperature and vegetation (LAI). It has about 9,000 outbreak records from May 2009 to June 2022, across 8 disease groups such as Acute Diarrhoeal Disease, Dengue, Malaria and Cholera.

We cleaned and imputed the data, did exploratory analysis, tested five hypotheses with standard statistical tests, and built models to predict whether a district will report an outbreak in a given month.

The main finding is that the delay between rain and outbreaks depends on how a disease spreads. Waterborne diseases follow the same month's rain; mosquito-borne Dengue and Chikungunya follow the previous month's, because mosquitoes need time to breed. Three independent methods showed this. Outbreaks are strongly seasonal (monsoon months have about 2.3× as many), and each disease has its own regional footprint.

Our models beat random guessing by 3–4×, but adding climate features didn't improve them: at regional resolution, rainfall only carries the seasonal pattern that the month and a district's own history already capture."

The storyline (in order)

  1. Data preparation: profile → clean → impute (with flags) → canonicalize district names.
  2. EDA: trends, seasonality, maps, distributions. Key discovery: count outbreaks, not cases.
  3. Hypothesis testing: 5 hypotheses using all 7 course tests, with effect sizes and corrections.
  4. Modeling: district × month classifiers, each compared with a no-climate baseline.
  5. Deployment: static report website on GitHub Pages.

Data facts you must know

  • The data ends in June 2022 (although the dataset is described as 2009–2023), so 2022 is a partial year.
  • 2020 reporting collapsed: 151 records vs. 570–1,110 per year before, most likely COVID disruption of surveillance, not less disease.
  • The 2009 Cholera outlier: South 24 Parganas, West Bengal, 51,225 cases in one week (the next highest Cholera record is 9,689). Present in the raw file; kept, because we can't verify whether it's real or an error. It's the reason we count outbreaks instead of cases.
  • Only outbreaks are recorded. There are no rows for "no outbreak", so for modeling we had to construct them.

3. EDA findings

Most important methodological insight: outbreak count beats case count. Total cases are dominated by a handful of extreme records, so case charts look spiky and random. Counting outbreak records reveals a clean, repeating annual cycle that matches rainfall. It changed several conclusions, e.g. Cholera's seasonal peak and the West Bengal Cholera "hotspot" (which was driven by the 2009 outlier).

4. Hypothesis-testing basics

Null hypothesis (H₀): the "nothing is happening" claim, e.g. "outbreaks are spread evenly across months".

Alternative (H₁): what we suspect, e.g. "outbreaks cluster in certain months".

We assume H₀ is true and ask how surprising our data would be.

p-value: the probability of seeing data at least this extreme if H₀ were true.

If p < α (we used α = 0.05), we reject H₀.

It is not the probability that H₀ is true, and not the size of the effect.

Type I error (false positive): rejecting a true H₀. Its probability is α.

Type II error (false negative): failing to reject a false H₀. Probability β; power = 1 − β.

One-sided vs two-sided: one-sided tests a specific direction ("monsoon is higher", H5); two-sided tests any difference. Use one-sided only when the direction was stated before looking at the data.

Parametric vs non-parametric

Assumption checks we used: Shapiro-Wilk (H₀: data is normal; small p → not normal) and Levene (H₀: groups have equal variances; small p → unequal).

Effect size: why p-values aren't enough

With ~9,000 rows, even a tiny difference gives a tiny p-value. The p-value says "is there an effect?"; the effect size says "how big is it?". H3 is the perfect example: p ≈ 10⁻³¹ but temperature explains only ~2% of the variation.

Multiple comparisons

If you run 20 tests at α = 0.05, you expect about 1 false positive by chance. Corrections control this:

  • Bonferroni: multiply each p by the number of tests m (or test at α/m). Simple but conservative. Used for H3's 28 pairwise tests and H4's 42 residual cells.
  • Holm: sort p-values ascending; multiply the smallest by m, the next by m−1, and so on (keeping the sequence non-decreasing). Same protection, more power. Used in H1 (10 tests per method) and H2 (8 diseases).

Autocorrelation

Consecutive months are similar (this July looks like last June's trend). Tests assume independent observations, so autocorrelation makes p-values too small. It affects H1 and H5; we state it as a limitation and rely on effect sizes, which are large enough that the conclusions hold.

5. The 7 tests

For each: what it asks, assumptions, the formula, and where we used it.

t-test (Welch's)

parametric2 groupscompares means

Asks: do two groups have different means?

Assumes: independent observations, roughly normal data (or large samples, by the central limit theorem). Student's t-test also assumes equal variances; Welch's doesn't, which is why we used it (Levene p ≈ 0.006 in H5).

t = (x̄₁ − x̄₂) / √(s₁²/n₁ + s₂²/n₂) df by Welch–Satterthwaite

Effect size: Cohen's d = (x̄₁ − x̄₂) / pooled SD.

Used in H5: monsoon vs non-monsoon monthly outbreak counts. t = 9.56, p ≈ 10⁻¹⁴, d = 1.91.

Mann-Whitney U

non-parametric2 groupscompares ranks

Asks: does one group tend to have larger values than the other? (Often described as comparing medians.)

Assumes: independent observations, ordinal or continuous data. No normality needed.

How: rank all values together; if one group's ranks are systematically higher, U is extreme.

U₁ = R₁ − n₁(n₁ + 1)/2 (R₁ = sum of group 1's ranks) rank-biserial r = 2U₁/(n₁n₂) − 1

Interpretation of r = 0.81: a random monsoon month beats a random non-monsoon month about (1 + 0.81)/2 ≈ 90% of the time.

Used in: H5 (main test, U = 4002, p ≈ 10⁻¹⁵) and H3's post-hoc pairwise comparisons.

One-way ANOVA

parametric3+ groupscompares means

Asks: are all group means equal, or does at least one differ?

Assumes: independence, normality within groups, equal variances (homoscedasticity).

F = MS_between / MS_within = [SS_between/(k−1)] / [SS_within/(N−k)] η² = SS_between / SS_total

Why not many t-tests? 8 groups = 28 t-tests, inflating Type I error. ANOVA tests everything at once; post-hoc tests then find which pairs differ.

Used in H3: F(7, 8038) = 18.9, p ≈ 10⁻²⁵, η² = 0.016. But assumptions failed (7/8 groups non-normal; Levene p ≈ 4×10⁻¹⁴), so we trusted Kruskal-Wallis.

Kruskal-Wallis H

non-parametric3+ groupscompares ranks

Asks: do the groups come from the same distribution? (Non-parametric ANOVA; extends Mann-Whitney to 3+ groups.)

Assumes: independence; similar distribution shapes if you want to talk about medians.

H = [12 / (N(N+1))] · Σ (Rᵢ² / nᵢ) − 3(N+1) ~ χ² with k−1 df ε² = (H − k + 1) / (N − k)

Used in H3: H(7) = 162, p ≈ 10⁻³¹, ε² = 0.019. Followed by 28 pairwise Mann-Whitney tests (Bonferroni) as the post-hoc.

Chi-square (χ²)

non-parametriccounts / categories

Two versions:

  • Goodness-of-fit: does one categorical variable follow an expected distribution? (H2: are outbreaks spread evenly over 12 months?) df = k − 1.
  • Test of independence: are two categorical variables related? (H4: disease × region.) df = (r − 1)(c − 1); expected E = row total × column total / N.
χ² = Σ (Observed − Expected)² / Expected Cramér's V = √( χ² / (N · (min(r, c) − 1)) )

Assumes: independent observations, counts (not percentages), expected count ≥ 5 in (almost) every cell, otherwise the χ² approximation breaks. Ours: min expected 7.2 (H2), 6.6 (H4).

Adjusted standardized residuals (H4) show which cells drive a significant result: |z| above the critical value means significantly more (+) or fewer (−) than expected.

Pearson correlation (r)

parametric2 numeric variableslinear

Asks: is there a linear relationship? r ranges from −1 to +1.

Assumes: linearity, roughly normal variables, no big outliers (sensitive to them).

r = cov(X, Y) / (s_X · s_Y) test: t = r√(n−2) / √(1−r²), df = n−2

Used in H1: rainfall at month t − lag vs. outbreak count at month t.

Spearman correlation (ρ)

non-parametric2 variablesmonotonic

Asks: as X goes up, does Y consistently go up (or down)? Not necessarily in a straight line.

How: Pearson correlation computed on the ranks. Robust to outliers and skew.

Used in H1 alongside Pearson. Where Spearman > Pearson (Malaria, Cholera at lag 1), the relationship is monotonic but not linear, or a few extreme months pull Pearson down. Both agreed on the strongest lag for every disease.

H3 · Temperature by disease

  • Only the 8,046 rows with measured temperature (imputation R² was only 0.17).
  • Assumptions: Shapiro-Wilk rejected normality for 7/8 diseases; Levene rejected equal variances (p ≈ 4×10⁻¹⁴) → Kruskal-Wallis is the test to trust.
  • ANOVA F(7, 8038) = 18.9, p ≈ 10⁻²⁵, η² = 0.016 · Kruskal-Wallis H(7) = 162, p ≈ 10⁻³¹, ε² = 0.019. Both reject.
  • Significant but tiny: disease explains ~2% of temperature variation. Most medians lie within ~2°C (29.0–31.0°C).
  • Post-hoc: 13 of 28 pairs differ. Chikungunya warmest (median 33.1°C), AES coolest (27.8°C), r = 0.50 between them.
  • Confound: Chikungunya is in the hot south, AES in the northeast, and temperature depends on location. So this is probably where diseases occur, not a temperature preference.

H4 · Disease depends on region

States grouped into 6 regions following India's Zonal Councils (North, Central, East, West, South, Northeast). "Other" excluded (a mixed label). χ²(30) = 1440, p ≈ 10⁻²⁸⁴, Cramér's V = 0.18 (medium-to-large for this table size).

  • Chikungunya → South (z = +18.6; 60% of its outbreaks). Strongest cell.
  • AES → Northeast (z = +16.8; 46%), and zero outbreaks in the South.
  • Dengue → South & West · Malaria → Central & Northeast, under-represented in the South · Cholera → North (Punjab/J&K).
  • The test compares each region's mix of diseases, so differences in total reporting volume between regions are largely factored out.

H5 · More outbreaks in monsoon months

  • Unit: one year-month's total outbreak count. Monsoon = Jun–Sep. One-sided (direction set in advance). 2020 and 2022 excluded (anomalies), with a sensitivity run including them.
  • Median 95 vs. 35 outbreaks per month (mean 98.7 vs. 42.5): about 2.3×.
  • Welch t = 9.56, d = 1.91 · Mann-Whitney U = 4002, rank-biserial r = 0.81. Both p < 10⁻¹³. The largest effect in the project.
  • Non-monsoon counts are skewed (Shapiro p ≈ 4×10⁻⁷) and variances unequal, so Mann-Whitney is more trustworthy; the t-test agrees because samples are large (48/92) and the gap is huge.
  • Including 2020/2022 weakens it a little (d 1.59) because their unusually low monsoon months pull the monsoon mean down.

7. Modeling theory

The prediction task

Binary classification: for each district and month, predict 1 (an outbreak was reported) or 0 (none). Forecasting national totals wasn't viable: only 158 monthly points, data ends mid-2022, and the last years are distorted.

Constructed negatives: the data only has outbreaks, so we built a full district × month grid (764 × 158 = 120,712 cells) and marked cells with no record as 0. Assumption: no record = no outbreak. It might really mean "not reported", which is a key limitation.

Logistic regression

A linear model for probabilities. It computes a weighted sum of features and squashes it into 0–1 with the sigmoid:

p(outbreak) = 1 / (1 + e^−(β₀ + β₁x₁ + … + βₖxₖ)) log(p / (1−p)) = β₀ + Σ βᵢxᵢ

Each coefficient changes the log-odds. Simple, fast, interpretable, but only captures linear (additive) effects. C is the inverse regularization strength (smaller C = stronger penalty on large weights); we tuned C ∈ {0.01, 0.1, 1, 10}. Numeric features were standardized; month and region one-hot encoded.

Gradient boosting

An ensemble of small decision trees built one after another. Each new tree is fitted to correct the errors (gradients of the loss) of all previous trees; predictions are the sum of all trees, scaled by the learning rate. It captures non-linear effects and interactions automatically.

We used scikit-learn's HistGradientBoostingClassifier, which bins features into histograms (fast on large data) and handles missing values natively. Tuned: learning rate {0.05, 0.1}, max leaf nodes {15, 31}, min samples per leaf {50, 200}, L2 regularization {0, 1} (16 combinations). Early stopping prevents adding trees once it stops improving.

Bagging vs boosting: Random Forest (bagging) builds trees independently on random samples and averages them, which reduces variance. Boosting builds trees sequentially, each fixing the last, which reduces bias.

Train / validate / test split, and why by time

SplitPeriodPurpose
TrainMay 2009 – Dec 2017Fit the model
Validate2018Choose hyperparameters and the yes/no threshold
Test2019Final score, used once, after refitting on 2009–2018
Stress test2020 – Jun 2022Behaviour under the COVID-era reporting shift

A random split would put 2019 rows in training and 2018 rows in testing, letting the model learn from the future (data leakage) and giving over-optimistic scores. Real use means predicting forward in time, so the test must be later than the training data.

Other leakage we avoided: all history features use only months before t (shift by 1); missing climate is filled from training-period averages only; the set of districts is chosen from the training period only.

Features

  • Season & place: month, region, latitude, longitude.
  • Climate: region's mean rainfall and temperature this month and last month (lag 0 and 1).
  • District history (past-only): outbreak last month, same month last year, count in the previous 12 months, long-run outbreak rate so far.

Why region-level climate? Climate values exist only on outbreak rows, so a district with no outbreak that month has no climate value. District averages were too sparse (median district: 5 outbreak months in 13 years).

Precision = 36/142 ≈ 0.25 · Recall = 36/162 ≈ 0.22. This is at the F1-optimal threshold. Lowering the threshold catches more outbreaks at the cost of more false alarms (≈50% recall at ~12% precision; ≈80% recall at ~8%). For public health, missing an outbreak usually costs more than a false alarm, so a lower threshold is reasonable. Random alerts would be right only ~4% of the time.

Baseline / ablation and permutation importance

Ablation: train the same model with and without the climate features. The difference is what climate adds. Without this comparison, "the model works" says nothing about climate.

Permutation importance: shuffle one feature in the test set and measure how much PR-AUC drops. A big drop = the model relies on it. Near zero or slightly negative = not useful (negative values are noise). Caveat: correlated features share credit; if rain and month carry the same information, shuffling one barely hurts because the other stands in.

Any-disease model (reference)

685 districts; logistic regression vs. gradient boosting, each with/without climate. All four reach PR-AUC ≈ 0.19–0.20 vs. 0.061 random (~3.2×); ROC-AUC 0.76–0.78. District history is the strongest signal. It's mostly an ADD model (ADD = 57% of records), which motivated splitting by transmission route.

Stress test 2020–22

PR-AUC drops (e.g. any-disease ≈ 0.12), but so does the base rate (2.6%), so the lift over random stays ~4.7× and ROC-AUC holds. The ranking of districts survives the COVID-era shift; the absolute probabilities are too high because the model was trained when outbreaks were more common.

A Dengue-only model was tried and dropped

The Aedes model matched it (0.185 vs. 0.169) with twice the positives, so it was redundant.

9. Limitations (know these cold)

  1. Reported, not actual, outbreaks. Surveillance capacity varies by state and year; a missing record may mean "not reported".
  2. No population normalization. Bigger districts naturally report more.
  3. Coarse climate. Models use regional monthly averages; region-month climate is averaged over outbreak locations, so it's biased toward them.
  4. Autocorrelation / shared seasonality. p-values for time-series tests (H1, H5) are optimistic.
  5. Correlation ≠ causation. Rain and outbreaks move together; we didn't prove rain causes outbreaks.
  6. Imputation is rough (R² 0.17–0.20), so we excluded imputed values where it mattered.
  7. Deaths unusable (71.6% missing).
  8. Small samples for some groups (AES 111, Anopheles 18 test positives).
  9. Districts created mid-period get zero-filled months before they existed.

Future work

District-level rainfall (IMD gridded data or CHIRPS) · neighbouring-district outbreak features (spatial spread) · population per district · bootstrap confidence intervals on model metrics · weekly resolution with lag features.

10. Viva questions

Try answering out loud before opening each one. Use "Quiz mode" to close all answers.

About the project & data

What is the objective of your project?

To understand how climate (rainfall, temperature, vegetation) relates to disease outbreaks in India, test specific hypotheses about that relationship, and check whether climate can help predict when and where outbreaks happen.

What dataset did you use, and what does one row represent?

EpiClim (Zenodo), built from IDSP surveillance data. Each row is one reported outbreak: district, week, disease, cases, deaths, and that district's rainfall, temperature and LAI. About 9,000 rows, May 2009 – June 2022.

What is LAI?

Leaf Area Index: leaf area per unit ground area, a satellite-derived measure of vegetation greenness. It was included as a proxy for mosquito habitat, but showed only weak relationships with outbreaks.

How did you handle missing values?
  • Temp (10.4% missing): linear regression on latitude + longitude (R² 0.17).
  • LAI (24.4%): regression on latitude + longitude + Temp (R² 0.20), clipped at 0.
  • preci (1.5%): median, because rainfall is skewed.
  • Deaths (71.6%): filled with 0 but not analysed.

We added *_imputed flags so imputed values could be excluded later, which we did in H3.

Why regression imputation instead of mean imputation?

Temperature varies strongly with location (correlation with longitude −0.37, latitude −0.30). A flat mean would give Kerala and Kashmir the same temperature. Regression uses location, so it's more realistic, although R² is modest, which is why we flagged and excluded imputed values in sensitive analyses.

Why did you count outbreaks instead of cases?

Case totals are dominated by a few extreme records; one 2009 Cholera record had 51,225 cases, more than 5× the next. Case charts looked spiky and random. Counting outbreak records reveals a clean seasonal pattern aligned with rainfall, and isn't distorted by one huge event. It changed conclusions, e.g. the West Bengal Cholera hotspot was really just the outlier.

Why didn't you remove the 2009 Cholera outlier?

It's in the raw source, and we can't tell whether it's a real large outbreak or an entry error. Deleting it would be an unjustified edit. Instead we used methods robust to it: outbreak counts and rank-based tests.

What's unusual about 2020 and 2022?

2020 has only 151 records (vs. 570–1,110 before), most likely COVID disrupting surveillance. 2022 is a partial year: the data ends in June. We excluded both from H5 and used them as a stress test for the models.

Why group diseases into 8 categories?

The raw data had 22 labels, many near-duplicates ("Dengue", "Suspected Dengue", "Dengue/Chikungunya"). We kept the 7 well-populated ones and grouped the rare remainder as "Other" so each category has enough data.

EDA

What was your most important EDA finding?

Two: outbreak counts reveal clear monsoon seasonality that case totals hide; and the rainfall-lag pattern (waterborne at lag 0, Aedes-borne at lag 1), which we then confirmed in H1 and in the models.

Your disease-to-disease correlations were high. Do diseases occur together?

Not necessarily. It's a confound: all diseases peak in the monsoon, so their monthly counts rise together even if they're unrelated. To test real co-occurrence you'd need to remove seasonality first and correlate the residuals.

Why did you use small multiples instead of one chart?

On a shared axis, one disease's spike (e.g. Dengue 2015) flattens all the others. Giving each disease its own panel and scale makes every pattern visible.

Why does West Bengal have so many cases?

Partly the 2009 Cholera outlier, partly population and reporting capacity. Raw totals aren't normalized by population, so states can't be fairly compared on burden from this data alone.

Statistics

What is a p-value? What is it not?

The probability of getting results at least as extreme as ours, assuming H₀ is true. It is not the probability H₀ is true, and it doesn't measure how big or important the effect is.

Your p-values are tiny (like 10⁻³¹). Does that mean the effect is huge?

No. With ~9,000 rows even trivial differences become significant. That's why we report effect sizes: H3 has p ≈ 10⁻³¹ but ε² = 0.019, meaning disease explains only ~2% of temperature variation. Significant, but not practically important.

Difference between Type I and Type II errors?

Type I: rejecting a true H₀ (false positive), probability α = 0.05. Type II: failing to reject a false H₀ (false negative), probability β. Lowering α reduces Type I errors but increases Type II errors.

When do you use parametric vs non-parametric tests?

Parametric (t-test, ANOVA, Pearson) when data is roughly normal without big outliers; more powerful when that holds. Non-parametric (Mann-Whitney, Kruskal-Wallis, Spearman) for skewed data, outliers or ranks. Our case counts and monthly counts are skewed, so we leaned on non-parametric tests and ran parametric ones alongside for comparison.

In H3, why trust Kruskal-Wallis over ANOVA?

ANOVA assumes normality and equal variances. Shapiro-Wilk rejected normality for 7 of 8 diseases and Levene rejected equal variances (p ≈ 4×10⁻¹⁴). Kruskal-Wallis needs neither. Both rejected H₀, so the conclusion is robust either way.

Why Welch's t-test and not Student's?

Student's t-test assumes equal variances. Levene's test showed unequal variances (p ≈ 0.006); monsoon months have SD 37 vs. 25. Welch's version doesn't assume equal variances.

Why was H5 one-sided?

Our hypothesis had a direction set in advance from domain knowledge: monsoon months have more outbreaks. A one-sided test is appropriate when the direction is stated before seeing the data.

Why run both a t-test and Mann-Whitney in H5?

To compare parametric and non-parametric approaches. Non-monsoon counts are skewed, so Mann-Whitney is more trustworthy; the t-test still agrees because the samples are large (central limit theorem) and the gap is very big.

Pearson vs Spearman: what's the difference and why use both?

Pearson measures linear association and is sensitive to outliers. Spearman is Pearson on ranks and measures any monotonic association, so it's robust. Using both checks the result isn't driven by a few extreme months; they agreed on the strongest lag for every disease.

Why did you need a multiple-comparison correction?

Running many tests inflates false positives: 20 tests at α = 0.05 give ~1 false positive expected by chance. We used Holm (H1, H2) and Bonferroni (H3 post-hoc, H4 residuals).

Holm vs Bonferroni?

Both control the family-wise error rate. Bonferroni multiplies every p by m. Holm sorts p-values and multiplies the smallest by m, the next by m−1, etc., so it's uniformly more powerful while giving the same protection.

What does Cramér's V = 0.18 mean in H4?

It measures the strength of association between disease and region on a 0–1 scale. For a 7 × 6 table (5 degrees of freedom for the effect), 0.18 is medium-to-large: region genuinely shapes the disease mix.

What are the assumptions of the chi-square test?

Independent observations, raw counts (not percentages), and expected count ≥ 5 in (almost) all cells. Our minimum expected counts were 7.2 (H2) and 6.6 (H4). We excluded "Other" from H4 because it's a mixed label.

In H2, why weren't the expected counts simply n/12?

The data runs May 2009 to June 2022, so May and June appear 14 times and other months 13. Even with no seasonality, those two months would get more records. We weighted the expected counts by how often each month appears.

Why exclude imputed temperatures in H3?

Imputed temperatures came from a location-only regression with R² 0.17, essentially "the typical temperature for that place". Including them would bias the comparison toward location, so we used the 8,046 measured values only.

Does H3 prove some diseases prefer warmer temperatures?

No. The differences are driven by Chikungunya (hot south) and AES (northeast). Temperature depends on location, so this likely reflects where diseases occur. Testing a true temperature effect would need comparisons within the same region.

Does rainfall cause Dengue?

Our analysis shows association, not causation. The lag-1 pattern is consistent with the known mechanism (rain → standing water → mosquito breeding → transmission), but correlation alone can't prove it. Rain and Dengue could also share other seasonal drivers like humidity or temperature.

Why is autocorrelation a problem?

Tests assume independent observations, but consecutive months are related. That makes the effective sample size smaller than it looks, so p-values come out too small. We noted it as a limitation; the effect sizes are large enough that the conclusions hold.

Isn't H5 the same as H2?

They overlap but answer different questions. H2 asks whether each disease is seasonal and in which month it peaks. H5 asks how much higher overall reporting is during the monsoon, as a size of effect (2.3×, d = 1.9), and compares a parametric with a non-parametric test.

Modeling

What exactly does your model predict?

Whether a given district will report an outbreak (of a given transmission group) in a given month: a binary classification on a district × month grid.

The data only has outbreaks. Where did the negative examples come from?

We built a full grid of every district and every month and marked cells with no record as 0. That assumes no record means no outbreak, although it could mean the district didn't report. We state this as a key limitation.

Why did you split by time instead of randomly?

A random split leaks future information into training: the model could learn from 2019 to predict 2018. Real use means predicting forward, so we trained on 2009–2017, tuned on 2018 and tested on 2019.

What is data leakage, and how did you prevent it?

Leakage is when information unavailable at prediction time sneaks into training, giving falsely good scores. We prevented it with a time-based split, history features that only use earlier months, filling missing climate from training years only, and choosing districts from the training period only.

Why not accuracy?

About 95% of district-months have no outbreak, so predicting "no" every time scores ~95% accuracy while being useless. PR-AUC focuses on how well we find the rare positives.

What does PR-AUC = 0.185 mean? Is that bad?

It's the area under the precision-recall curve (average precision). A random model scores the positive rate, 0.043 for Aedes, so 0.185 is about 4.3× better than random. In absolute terms it's modest: at the chosen threshold, about 1 in 4 alerts is real. That's typical for surveillance data, which is noisy and sparse.

ROC-AUC vs PR-AUC?

ROC-AUC is the probability a random positive is ranked above a random negative (random = 0.5). With heavy class imbalance it can look flattering because the many easy negatives inflate it. PR-AUC ignores true negatives and focuses on the positives, so it's more informative for rare events.

Interpret your confusion matrix.

Aedes, 2019: caught 36 of 162 outbreaks (recall 22%), with 106 false alarms (precision 25%), 126 missed, 3,512 correct "no" predictions. That's at the F1-optimal threshold; lowering it catches more outbreaks (≈80% at ~8% precision) at the cost of more false alarms. For health officials, missing outbreaks is usually worse.

How did you choose the threshold?

On the 2018 validation year, we picked the threshold that maximized F1. It's a choice; in practice it should reflect the relative costs of missed outbreaks and false alarms.

Why compare against a no-climate model?

It's an ablation: the only way to know what climate adds. A good overall score could come entirely from season and district history. The comparison isolates climate's contribution.

H1 found strong rain–outbreak correlations. Why didn't climate improve the model?

Regional monthly rainfall mostly encodes the seasonal cycle, which the month feature and district history already capture. Feature importance shows this: when rainfall is added, the month feature drops to near zero. The model uses rainfall instead of month, as a seasonal clock, not as extra information. So climate and outbreaks move together, but at this resolution climate adds nothing beyond "what month is it".

Explain logistic regression.

It models the log-odds of an outbreak as a weighted sum of features and converts it to a probability with the sigmoid, 1/(1 + e^−z). Coefficients are learned by maximizing likelihood, with L2 regularization controlled by C. Interpretable, but only linear effects.

Explain gradient boosting.

An ensemble of small decision trees built sequentially; each new tree corrects the errors of the ones before it. Predictions are the sum of all trees, scaled by the learning rate. It captures non-linear effects and interactions. We used HistGradientBoostingClassifier, which bins features for speed and handles missing values natively.

Logistic regression and gradient boosting scored about the same. What does that tell you?

The relationships in our features are mostly simple; non-linear modeling didn't find extra structure. The limit is the information in the features, not the model's flexibility.

How did you tune hyperparameters?

Grid search: train on 2009–2017 with each setting, score PR-AUC on 2018, keep the best. Then refit with those settings on 2009–2018 (more data) and evaluate once on 2019. The test set was never used for choices.

What is permutation importance?

Shuffle one feature's values in the test set and measure how much PR-AUC drops. A big drop means the model relies on that feature. Negative or near-zero values mean it doesn't help (negatives are just noise). Correlated features can share importance.

Why split models by transmission route?

H1 and H4 showed diseases respond to rain with different lags and occur in different regions. The any-disease model was mostly ADD (57% of records) and mixed opposite patterns. Grouping by mechanism (waterborne, Aedes, Anopheles) is biologically meaningful, and the models then picked the matching rainfall lag.

Why separate Aedes and Anopheles? Aren't both mosquitoes?

Different mosquitoes with different ecology. Aedes (Dengue, Chikungunya) breeds in small containers near homes, and is mostly urban, South and West. Anopheles (Malaria) is more rural and is concentrated in Central India and the Northeast. In H1 Malaria didn't share the clean lag-1 pattern.

Why exclude AES?

Acute Encephalitis Syndrome is a syndrome with many causes (Japanese encephalitis, which is mosquito-borne, but also others), so it doesn't fit one transmission route. It also has only 111 records.

Can we trust the Anopheles model?

Not much. Malaria reporting thinned after 2016, leaving only 10 validation and 18 test positives. One or two lucky hits move PR-AUC a lot. We present it as suggestive only.

What does the stress test show?

On 2020–22 the base rate fell (2.6% for any disease), so PR-AUC fell too, but lift over random stayed ~4.7× and ROC-AUC held. The model still ranks districts well under the COVID-era shift; its absolute probabilities are too high because it was trained when outbreaks were more common.

How would you improve the model?
  • District-level rainfall from IMD gridded data or CHIRPS (the biggest potential gain for climate).
  • Outbreaks in neighbouring districts last month (spatial spread).
  • Population per district.
  • Weekly resolution with lagged features; bootstrap confidence intervals on metrics.

Deployment, process & general

How is the project deployed?

A static report website (HTML + plot images) in the repo's docs/ folder, served by GitHub Pages from the main branch. Every push updates it. The analysis itself is reproducible Python scripts.

How can someone reproduce your results?

pip install -r requirements.txt, then run the numbered scripts in scripts/ in order from the repo root: 01–03 prepare data, 04–19 EDA, 20–24 hypothesis tests, 25–28 models. Derived files are regenerated, not committed.

What was the hardest part?

Good answers: realising case totals were misleading and switching to outbreak counts; building "no outbreak" rows that the data doesn't contain; and keeping the model free of leakage with past-only features and a time-based split.

What would you do differently?

Get district-level climate and population data from the start; check week/date alignment and duplicates earlier; and plan the hypotheses before doing EDA, to avoid testing patterns found in the same data.
